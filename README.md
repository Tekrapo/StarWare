# s2ext — Standoff 2, внешний вариант на анализе экрана

Отдельное приложение. Не читает память игры, не требует root, не ставит ничего
в APK игры. Работает только с тем, что игра нарисовала на экране.

## Что внутри

| Файл | Назначение |
|---|---|
| `capture/CaptureService.kt` | MediaProjection → ImageReader (половина разрешения), foreground-сервис, оверлей |
| `detect/Detector.kt` | поиск кластеров красных пикселей (полоски HP), фильтр по форме |
| `detect/Target.kt` | прямоугольник найденной полоски в координатах кадра |
| `overlay/OverlayView.kt` | нетронутое окно `TYPE_APPLICATION_OVERLAY`: рамки + круг FOV |
| `aim/AimService.kt` | AccessibilityService, `dispatchGesture` — короткий свайп из центра |
| `data/Settings.kt` | флаги и калибровка, SharedPreferences |
| `MainActivity.kt` | весь UI, запросы разрешений, START/STOP |

Поток данных: экран → MediaProjection → RGBA-буфер → детектор → оверлей.
Аим: детектор → ближайшая цель в круге FOV → свайп через accessibility.

## Сборка

На телефоне APK не собирается: там нет JDK, Android SDK, Gradle, aapt2 и d8,
а запуск скачанных бинарников из данных приложения запрещён SELinux
(`Permission denied`). Сборка — на ПК или в GitHub Actions.

### Вариант 1: ПК

Нужны JDK 17 и Android SDK 34.

```bash
cd s2ext
export ANDROID_HOME=/путь/к/Android/Sdk
./build.sh
```

`build.sh` сам создаст `local.properties`, сгенерирует Gradle wrapper, соберёт
debug-APK и положит его рядом как `s2ext-debug.apk` со sha256.

Вручную то же самое:

```bash
gradle wrapper --gradle-version 8.7
./gradlew :app:assembleDebug
# app/build/outputs/apk/debug/app-debug.apk
```

### Вариант 2: без ПК, GitHub Actions

1. Создайте репозиторий на github.com (можно с телефона в браузере).
2. Загрузите туда **содержимое** папки `s2ext` (чтобы `app/` и `.github/` были
   в корне репозитория).
3. Вкладка **Actions** → workflow **build-apk** → **Run workflow**.
4. Через 2–3 минуты в разделе run появится артефакт `s2ext-debug-apk.zip`.
   Внутри — готовый `app-debug.apk`.

Workflow уже лежит в `.github/workflows/build-apk.yml`, ставит JDK 17,
Android SDK 34 и собирает `assembleDebug`.

## Первый запуск

Приложение по очереди попросит:

1. **Оверлей** — «Поверх других приложений» (`SYSTEM_ALERT_WINDOW`).
2. **Запись экрана** — системный диалог «Начать запись или трансляцию?».
   Это и есть тот самый запрос доступа, который в чужих читах называют
   «доступом VPN». VPN здесь ни при чём.
3. **Специальные возможности** — только если нужен аим (кнопка
   «Enable aim service» → включить «S2 External»).
4. **Уведомления** — на Android 13+, чтобы сервис не убивался.

Дальше: **START** → согласие на запись экрана → сервис поднимается →
запускается Standoff 2 (галочка «Launch the game after START»).

## Калибровка

- **FOV** — радиус, в котором аим ищет цель. В пикселях экрана.
- **Aim step** — минимальный интервал между свайпами (мс). Меньше = резче,
  больше = плавнее и меньше похоже на робота.
- **Aim gain** — множитель перевода «пиксели цели → пиксели свайпа». Зависит от
  чувствительности в игре. Подбирается вручную: если прицел не доезжает —
  увеличить, если проскакивает — уменьшить.

Порог красного задан константами в `Detector.kt` (`MIN_R`, `MAX_GB`,
`MIN_DELTA`). Если на карте другой свет или скин оружия даёт ложные срабатывания,
крутить надо там.

## Честные ограничения

- **Wallhack невозможен.** Приложение видит только нарисованные пиксели. Всё,
  что за стеной, игра не рисует — значит, и подсветить нечего.
- **Приложение закреплено в ландшафте** (`sensorLandscape`). Это не косметика:
  MediaProjection на Android 14 разрешает только один `createVirtualDisplay()`
  на токен согласия. При смене размера экрана используется документированный
  путь `VirtualDisplay.resize()` + `setSurface()`, а не повторное создание.
- **Задержка 1–2 кадра** (обработка раз в 80 мс). Для ESP нормально, для аима
  по движущейся цели — заметно.
- **Аим только по видимой цели.** Полоска HP должна быть на экране.
- **Точность аима пиксельная.** Это не запись углов, а синтетический свайп:
  поведение зависит от чувствительности, может дёргаться и мешать своему же
  касанию.
- **FLAG_SECURE.** Если игра помечает окно защищённым, MediaProjection отдаёт
  чёрные кадры. В лог пишется `frames are black - the game may set FLAG_SECURE`,
  и тогда этот способ не работает вообще. Это проверяется только на живом
  билде игры.
- **Детектор эвристический.** Ложные рамки возможны (красные вывески, кровь,
  HUD). Фильтр по форме (широкий и низкий прямоугольник) отсекает часть, но не
  всё.
- **VPN-разрешение не запрашивается.** `VpnService` маршрутизирует пакеты и не
  даёт доступа ни к памяти, ни к экрану. Добавлять его ради «как у других» —
  обман.
- **Бан.** Standoff 2 — сетевой PvP. Поведение синтетического аима и оверлей
  могут быть замечены. Гарантий «не детектится» нет и быть не может.

## Что проверено, а что нет

Проверено статически: баланс скобок, отсутствие заглушек, согласованность
манифеста и классов. **Не проверено:** сборка (на телефоне нет JDK/SDK/Gradle),
работа детектора на реальных кадрах Standoff 2, реакция игры на оверлей и
свайпы, FLAG_SECURE. Всё это — только на ПК + живом устройстве.
